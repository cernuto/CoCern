Draft for review, 2026-11-03. Basis: the approved [auto-connect design](../superpowers/specs/2026-11-03-auto-connect-design.md), especially “How it works” parts 8–11 and acceptance gates 6–10, read at `ecaff26e87622e17db481c840b2cf8fa65cebd84`.

**Status: every case below is NOT RUN.** This document defines acceptance work; it does not declare proposed features implemented or reuse an earlier smoke result as a new-feature pass. No hub, client settings, node process, live grant, or C# source was changed while drafting it. Root owns implementation/deployment, 3aa owns later integration, and this branch owns this document only.

## Run contract and evidence

- Use a disposable hub, database, certificate store, client profiles and node folder. Include a worker and administrator with separate test credentials, two manager candidates, and two independent hub identities. Prove path isolation before any fixture writes. Never run certificate removal, failed-update injection, session closure, handoff or approval tests on the shared hub.
- Build/deploy owners provide the candidate binaries and exact commit/hash. The existing [smoke script](../../scripts/Smoke-CoCern.py) selects the newest Debug/Release output by modification time; it has no per-case command-line selector. Verify its selected `HOST` and `ADAPTER` hashes match the candidate, or add an explicit candidate-selection fixture before claiming candidate coverage.
- “Existing” below means a reusable baseline, not coverage of the new contract. “Extend” means a new scenario is required. Proposed tool names in the design, such as `add_pc`, are not assertions that those tools exist. Record the implemented public operation/schema when it becomes available; an absent operation leaves its case NOT RUN with a blocker.
- For each case record: case ID, candidate commit and binary hashes, fixture ID, UTC start/end, request/correlation IDs, expected and actual result/status, before/after nonsecret state, and evidence path. Keep secrets and raw authentication headers out of evidence; compare credential/session/cache invariants privately and publish only booleans. A tool list or request accepted by the relay is never proof of authority or a model wake.
- Mark PASS only after the required observations match. Skipped, unavailable, unimplemented, pending review and untested client surfaces remain NOT RUN. A tested mismatch is FAIL. Record a bounded timeout chosen before the run; do not turn missing evidence into success.

### Required native-client and PC release coverage

Protocol fixtures support these journeys; they never replace a real native chat or genuinely separate PC. All required journeys must pass before declaring the release accepted. An unavailable client or second PC leaves the release gate incomplete, not green. Record native chat ID, client/version, physical PC identity, candidate build, user interaction count, actual tool/result transcript and correlated state changes, with secrets redacted.

No simulated client or separate MCP probe substitutes. |

Synthetic human-origin protocol records remain supporting data, never permission on the real hub. |
| Runtime capability and wake behavior | Existing native Codex and Claude chats on supported client surfaces, with their actual loaded metadata and normal wake paths; updater journey on the separate joined PC. | 9.2–9.4 and 10.3–10.5: backend/loaded-client distinction, first-use tool success, prior turn completion, quiet interval and new native turn with nonce. Failure injection and destructive fixture operations still use disposable state under the run contract. If a real-client journey cannot be isolated without touching live settings or grants, obtain an approved isolated test setup rather than execute it against the shared service.
