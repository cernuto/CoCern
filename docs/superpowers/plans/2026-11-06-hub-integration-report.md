# Hub identity and profile integration source report

Source implementation and review only; runtime behavior remains unverified. No tests, builds, packages, deployments, live probes, restarts, settings changes, or board changes were performed.

- `CallGuard` verifies attached acting-session proof for every tool, rejects incomplete proof or a direct own-session proof that differs in ID or token, and enforces `SessionToolProfiles.Allows` on the authenticated actor. A standalone credential with no session remains credential-scoped. Direct session context remains separate from acting-only context so target arguments and session-specific add-ons retain their meaning.
- A bounded typed `NativeCurrentQuery` reads the control aggregate without replay caching. `ControlState.CurrentNativeActor` checks the authenticated principal, token, repository, actual session, current native generation, uniqueness and closing fence before the caller receives a verified participant. Missing current proof leaves no participant; goal and peer paths reject it, while unrelated raw workflows do not acquire native authority. The protected file path independently revalidates its stronger file scope.
- `DomainSurrogates` refuses an entire malformed goal member list instead of silently dropping invalid entries. `GoalTools.ApproveAsync` requires the verified actor, resolves bounded distinct current members, and checks a replay receipt before resolving selectors. Current registry checks are point-in-time and cannot by themselves freeze a later replacement across separate aggregates.
- `RelayApplication` applies fresh actor settings metadata after either ordinary or protected-file dispatch and after replay, rather than using a historical receipt or target identity. If the actor can no longer be verified, no metadata is attached. Native watcher presence requires a successful authenticated background inbox read and current native actor and remains advisory. Settings mutation retains its credential-derived administrator, open exact target, repository, version and audit checks; internal composition alone does not grant administrator authority.
- `RelayApplication.ReadSessionToolSettingsAsync` and the read-only session aggregate operation let an authenticated administrator read an open exact target's profile, revision and explicit flag, without a target token, activity update or target identity disclosure beyond the requested session.

Roslyn CodeLens targeted the active CoCern solution; Visual Studio reported the unrelated M3TS-SNX solution and was left unchanged. Roslyn compiler diagnostics reported zero errors for CoCern.Core and CoCern.Domain after these edits. This is static evidence, not a build or runtime acceptance. Runtime checks of profile refresh, actor/target mismatch, replacement and close races, replay, protected files and native watcher behavior remain deferred until explicitly authorized. Separate review of goal bindings and lost-binding behavior was reported to the integration owner.

Follow-up source review moved freshly authenticated settings metadata ahead of add-on composition, token and wire fitting, and proposal reservation on both dispatch routes. Session-open is wire-bounded after enrichment, and an enrichment that cannot fit is omitted. Unchanged compact status replies preserve metadata. Nothing is appended after proposal reservation. Roslyn Core compiler diagnostics again reported zero errors; no runtime checks were performed.
