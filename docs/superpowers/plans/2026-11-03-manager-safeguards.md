# Manager Safeguards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record one explicitly selected manager and provide administrator-controlled dashboard recovery before that selection can confer any additional power.

**Architecture:** Extend the existing singleton ControlGrain state and control_request commands, retaining authenticated RelayCaller authority, state-machine idempotency, and existing pause/cancellation behavior. Store the current assignment and bounded selection history in the same aggregate transaction; expose only explicit redacted projections. Add authenticated dashboard selection and dispatch controls without depending on the selected manager or changing alert routing.

**Tech Stack:** C#/.NET 10, Orleans coordination aggregates, SQLite persistence, ASP.NET Core dashboard endpoints, Blazor dashboard, xUnit.

**Spec:** docs/superpowers/specs/2026-11-03-auto-connect-design.md, parts 9–11, acceptance gates 9–10, and order item 10. This plan implements the safeguard prerequisite, not the complete gates or the later administrative powers.

## Global Constraints

- “The name doesn't grant the power”: labels and the self-reported session role never authorize selection or administration.
- “One manager at a time”: a single hub-wide assignment, not one assignment per repository.
- “A chat never grants itself more power because the work seemed to call for it.” Assignment remains inert in this plan: no caller elevation, changed manager alert routing, administrative tool expansion, setup changes, or removal of COCERN_ROLE/COCERN_PROFILE.
- “What it can't do: see other chats' private tokens or sign in as them.” Never serialize raw DirectoryEntry, SessionRecord, control JSON, or credentials into these new responses.
- Selection requires existing administrator authority and explicitly recorded human words. The hub trusts that administrator's attestation; it cannot verify that the human actually spoke. A peer message, a quoted peer assertion, or a label never supplies authority.
- Preserve the complete current assignment's actor, time, request ID and human words independently of bounded history eviction. Reject an oversized quotation; never silently truncate quoted words.
- The 20-entry selection history is a bounded durable selection record, not the full durable every-manager-action audit required before later powers. Ordinary CallTelemetry is best-effort and is not that future audit.
- Dashboard sign-in, existing Standing removal, and existing session cleanup remain usable without a manager. Pause prevents new claimed/action work; stop requests cancellation and does not force-stop IDE tools or suppress wakes.
- Both Roslyn CodeLens and Visual Studio MCP are mandatory at each implementation task's start. Verify exact targets; use Roslyn semantic tools for C# inspection/diagnostics. Keep Visual Studio on the primary running solution, do not switch or rebuild it, and use isolated artifact outputs for necessary test binaries.

## Review Focus

- A stale or replayed handoff must neither replace a newer manager nor add a second selection-history entry; Task 1 pins generation conflicts, identical retries and changed-argument retries.
- Closing a manager, delayed lifecycle messages and an unrelated chat using the same label must not transfer its assignment; Task 1 pins unavailable-target behavior and explicit recovery.
- A worker scoped to another repository must not learn manager identities, actors, quotations or history; Task 1 pins redaction through both direct control status and composed session get_status.
- Lost HTTP responses, stale forms and missing observations must leave dashboard recovery usable and must not automatically overwrite a newer assignment; Task 2 pins request reuse, conflict display and manager-independent controls.
- Global stop must reach each known session and preserve unresolved-action records while making no claim to interrupt tools or wakes; Task 2 pins cancellation requests, boundary refusal and honest UI copy.

### Task 1: Inert singleton selection, bounded history, commands and redacted status

**Consumes:** existing RelayCaller.MayAccess(string), ControlState.Entry(string), ControlState.AwaitingAnswer(string, DateTimeOffset), CoordinationStateMachine.Apply(...), AggregateHub.Apply(...), AggregateHub.Clone(), AggregateHub.Data(RelayReply), and StatusTools.StatusAsync(RelayCaller, JsonObject, bool).

**Produces:**

- ControlState.ManagerGeneration: long, initial 0; ControlState.Manager: ManagerAssignment?; ControlState.ManagerHistory: JsonArray. State keys are managerGeneration, manager, managerHistory. Defaults must tolerate older state with none of these keys.
- ManagerSelection.Apply(AggregateContext context): RelayReply handles only appoint_manager and clear_manager, called after the existing administrator gate. ManagerSelection.Status(ControlState state, RelayCaller caller, DateTimeOffset now, long? historyBefore): ManagerSelectionStatus produces an explicit allowlisted view.
- Contracts: `ManagerSelectionSummary(string SessionId, string RepositoryId, long Generation, bool Available)`; `ManagerSelectionHistory(long Generation, string Command, string? PreviousSessionId, string? SessionId, string RepositoryId, string ActorPrincipalId, string RequestId, DateTimeOffset At, string HumanWords)`; `ManagerSelectionStatus(long Generation, ManagerSelectionSummary? Current, ManagerSelectionHistory[] History, long? NextHistoryBefore, bool HistoryTruncated)`.
- Wire commands remain POST /api/tools/control_request with repositoryId, requestId and command. appoint_manager additionally requires targetSessionId, expectedManagerGeneration and humanWords. clear_manager requires expectedManagerGeneration and humanWords and rejects a supplied targetSessionId. These commands do not require or return another session's token.
- get_status adds a manager property of ManagerSelectionStatus in its control result; composed session status naturally exposes control.manager. Optional managerHistoryBefore is a nonnegative whole JSON integer, excludes entries with generation >= that value, and is administrator-only. History is newest-first. Workers receive History=[], NextHistoryBefore=null and HistoryTruncated=false. Their Current is null unless caller.MayAccess(current.RepositoryId); their Generation is 0 when a current assignment belongs to an inaccessible repository. Administrators see the global assignment and bounded selection history across repositories.
