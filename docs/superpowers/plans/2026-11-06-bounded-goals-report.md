`StandingPreferences.Goals`, `StandingPreferences.Decisions`, `StandingPreferences`, `BoardState`, `AggregateContext`, `TaskWorkflow`, and `TaskBoardAggregate` implement versioned goal decisions, exact evidence, bounded membership, explicit finite UTC expiry, immutable private goal bindings, authorization checks, owner-only completion and linked proposals. Public grant and history summaries contain no stable participant IDs. `AttentionSources` and `ControlAggregate` route blocked, failed, stranded and completion attention through the current native owner registry; dashboard recovery remains available if the owner is absent.

`CoordinationStateMachine` rechecks goal authority for claim/action replays and provides internal read-only decision-receipt and execution probes. `TaskActions` passes current verified participant context; `ClaimComposer` rechecks after resource acquisition/blocking and rolls back or returns a non-executable action pending response when authority is gone. `SqliteStore.Standing`, `RelayObservation`, `ReplyAddOns`, and `GoalPresentationCandidates` select only sanitized owner-eligible proposal candidates, re-read the live board before fitting the actual reply, and atomically recheck owner and terms at reservation. The storage scan keeps private bindings in its input only. Existing six-argument pending-presentation callers still suppress goal-linked items when they cannot supply a verified owner.

`CoordinationStateMachine.GoalDecisionReplayProbe` accepts the unchanged original goal decision arguments and the internally verified caller, returning `{found:false}` or `{found:true,receipt,code,version}`; mismatches and buried requests refuse. Root's GoalTools consumes that shape before resolving participants. Central integration must preserve verified participant context across all authenticated session boundaries, verify the actor is still the current native registry session, and maintain strict schema and caller-field stripping.
