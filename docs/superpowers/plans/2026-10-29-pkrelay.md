# PkRelay Implementation Plan

> For agentic workers: use bounded fresh implementers, focused review, and an integration review. The coordinating chat retains decisions and verification.

**Goal:** Deliver a runnable coordination-only relay with durable cross-chat task continuity, HTTP/MCP/SignalR surfaces, and a local stdio adapter.

**Architecture:** One ASP.NET Core host runs one Orleans silo and a custom SQLite grain storage provider. Four grains own sessions, task boards, resource locks, and control/registration; agents continue using their existing IDE tools directly.

**Tech Stack:** .NET 10, ASP.NET Core, Orleans 10, Serilog, Scalar, OpenAPI, Microsoft.Data.Sqlite, official MCP C# SDK, xUnit.

**Spec:** `docs/architecture.md` (copy of the approved Desktop document).

## Global Constraints

- Coordination only: no IDE proxy, custom VS extension, tool runner, or extra scheduler.
- Authenticated repository-scoped calls; separate session handles/private inboxes, bounded output, optimistic versions, request deduplication, and honest partial outcomes.
- SQLite WAL/FULL; atomic state/ETag/due-work writes; tombstone generations; exclusive hub ownership; restart recovery.
- Keep uncertain external actions and restoration blockers beyond lease expiry. Required tool/client approvals remain with existing clients.
- Every C# worker loads Roslyn CodeLens skill and checks BOTH Roslyn CodeLens and visualstudio, using semantic tools for code inspection/diagnostics. The existing SNX VS instance must remain unchanged; use a separate PkRelay instance.
- No AI coauthor attribution or hard-wrapped commit/PR prose.

## Review Focus

- A storage conflict or failed commit must not leak uncommitted in-memory changes or publish effects.
- Parallel chats of one principal cannot access each other's private handles/inboxes; repository access is checked on every public operation.
- Composed acquisition rolls back only grants acquired by that attempt; unknown external operations remain blocking after lease expiry.
- Restart after recipient delivery but before sender acknowledgement must deduplicate the effect, retain unread messages, and avoid external execution.
- Test success does not erase cleanup obligations or promote synthetic coverage to live acceptance.

## Tasks and boundaries

Consumes `StateEnvelope<T>`, `IHasDueWork`, `IDueWorkSource` from Core. Produces `SqliteStore` implementing IDueWorkSource and `SqliteGrainStorage` implementing IGrainStorage, with `AddPkRelaySqlite(ISiloBuilder, string databasePath)` registration.

- [x] Write and run failing tests for create/read/write, stale ETags, tombstone recreation, atomic due-work replacement, backup/restore, second-hub rejection, and reopen persistence.
- [x] Implement the common envelope provider, safe initialization/migrations, exclusive lock, backup, and deterministic due index.
- [x] Run covering tests and complete independent storage review; final suite includes 11 SQLite cases and no open storage findings.

### Task 2: Coordination domain

Files: `src/PkRelay.Core/` except shared contracts, `tests/PkRelay.Tests/CoordinationTests.cs`.
Consumes shared contracts and named storage `relay`. Produces four grain classes with grain type names `pkrelay.session`, `pkrelay.board`, `pkrelay.lock`, `pkrelay.control`; `RelayApplication : IRelayApplication`; and `AddPkRelayCore(IServiceCollection)` registration.

- [x] Write and run failing behavioral tests for fresh chat handles/private inboxes, task updates/version conflicts/idempotency, cross-PC resource aliases, acquisition rollback, action uncertainty/cleanup holds, control pause, and persisted effect deduplication.
- [x] Implement the architecture's logical coordination tools and bounded context/messages/reports with authenticated caller checks. Use `repositoryId`, optional `boardId` (default `default`), `taskId`, `sessionId`/`sessionToken`, and `requestId` arguments. No caller identity is accepted from tool JSON.
- [x] Use durable outbox effects and generic due records; expose an internal due-work dispatch operation. Never invoke native chats/IDEs from a grain.
- [x] Run covering tests and resolve independent review findings; final suite includes 29 Core cases and all reviewed fixes.

### Task 3: Host and adapter

Files: `src/PkRelay.Host/`, `src/PkRelay.Adapter/`, HTTP/MCP/SignalR integration tests, README and scripts.
Consumes IRelayApplication, ICoordinationNotifier, IDueWorkSource and storage/core registrations. Produces authenticated REST at `/api/tools/{tool}`, remote MCP at `/mcp`, SignalR at `/hubs/coordination`, OpenAPI at `/openapi/v1.json`, Scalar at `/scalar`, and a stdio adapter forwarding only coordination tools.

- [x] Configure Serilog without body/secret logging; local client tokens and optional external JWT validation; loopback defaults; no insecure remote fallback. Configure Scalar/OpenAPI and background effect delivery.
- [x] Implement stdio forwarding, client-side SignalR hints, explicit inbox recovery, and documented setup. No wakeup capability is promised for unsupported clients.
