# Native activation source checkpoint

Status: planning source only and inactive. No installed-client permission evidence has been established, and neither native promotion nor file-claim hooks were installed or activated.

`CodexNativeSetup.Inspect` now distinguishes a missing private candidate from a candidate whose helper version is older but whose provider, connection, profile, scope and definition still pass `NativeRegistration.Read`. Both paths give a specific recovery action. A malformed or foreign candidate remains a verification error. An old candidate is not permission evidence.

`NativeJoinHook.RunAsync` consumes externally supplied stdin while `NativeRegistration.Read` validates private candidate identity and integrity; neither authenticates an installed client's permission decision. `NativeStartupEvidence` is not a permission attestation. Candidate presence, startup evidence and caller-supplied JSON are not accepted as permission proof.

`NativeActivation.PlanPromotion` and `ClientSettings.PlanNativePromotion` gate an explicit Codex choice on a current private registration, exact owned standard launcher, enrolled connection, running helper and fresh operator confirmation. The optional interactive confirmation explicitly asks the operator to check allow, ask, cancel and deny outcomes in the installed client and enter a fixed phrase. It refuses redirected input or output, shows the provider, profile, helper, candidate definition and enrolled scope, then writes a private credential-authenticated receipt expiring after five minutes. It is an operator attestation under the same-user trust boundary, not a client-generated permission attestation. The planner validates the receipt against the current candidate, scope, helper and expiry; there is no public JSON or Boolean success input. A missing, changed or stale receipt yields `permission_verification_required`. No confirmation or client check has occurred here.

`NativeActivation.PlanFileClaims` prepares explicit enable or disable plans for exact owned Codex and Claude Code PRE, POST and POST failure handlers. The opt-in is scoped to each hook process; ordinary setup does not invoke the planner. It requires a current owned enrolled connection and helper, and enabling also requires exact installed native hook entries. It retains modified or disabled entries and unrelated handlers. Removal only removes the exact generated entries. Local credentials, development invocation and historical helper commands remain unsupported. The existing scope, replay and lifecycle fences remain mandatory.

Claude file-claim commands use POSIX single-quote literals for the executable and every argument. Existing Claude native candidates use the older Windows argument quoting, so candidates with shell-expanding or ambiguous path characters are refused rather than trusted. Before either file-claim action, the planner scans the profile's hook entries for recognized file-claim markers; a historical, edited or otherwise non-exact entry returns `stale_file_claim_hooks_review_required` and leaves every handler intact for explicit review. This conservative check may also refuse another marked handler in the same profile.

`NativeSettingsTransaction` provides explicit future Windows apply and recovery methods: it checks a fresh plan, locks existing ordinary target files and launcher, candidate, enrollment, credential, helper and relevant receipt inputs against concurrent writes, compares preview snapshots and input digests, revalidates registration and evidence, and stores bounded private before/after images in a flushed journal before writing. Recovery restores known before/after states and refuses to overwrite a partial or externally changed file; in that case it retains the journal for manual recovery. It refuses absent targets, links, oversized journals and non-Windows apply. These APIs have not been executed or verified and still need independent source review and authorized testing. Standard setup remains usable and never silently promotes.

Root integration: `NativeActivationCommand.Run(args, dotnet, adapter, clock, output, error)` implements the explicit source command syntax `--native-activation <preview|confirm|apply|recover> <codex|claude> <promotion|enable|disable> --connection <folder> --profile <folder>`; promotion and confirmation currently support Codex only.
