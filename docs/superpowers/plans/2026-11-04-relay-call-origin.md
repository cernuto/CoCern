# Reported relay call origins

This feature starts from deployed main `5acb9ef0a770ba33e21f830094d294059ae3ae5a` on `codex/origin-compaction-cycle1`. It records a bounded call-path tag so producers can be compared without changing the existing model/background classification or traffic totals.

The exact recognized values are `mcp`, `claude-stop`, `claude-waiter`, `wake-watcher`, `node` and `dashboard`. Missing, invalid, differently cased and future values stay unknown. The tag is untrusted telemetry, never identity, authorization or evidence of model execution. It is removed before strict native envelope validation and aggregate/replay processing. Telemetry reuses its existing original-arguments input, avoiding additional CallGuard or CallTrace plumbing.

Storage adds nullable `activity_log.call_origin` and a small `activity_origin_daily` companion keyed by day, repository, tool and origin. Its counters roll up in the same transaction as existing totals and raw-row deletion. The existing daily primary key and `tool_traffic` shape/totals are unchanged. The new `tool_origin_traffic` view combines raw rows, companion rows and residual historical totals as unknown without double counting. Snapshot conversion adds absent schema only to the converted copy; historical origins are never inferred.

Verification: the twelve new cases failed against the original implementation while all three existing cases passed, then all fifteen passed after implementation. Two additional native-preflight cases failed when early tag stripping was deliberately removed. Final verification passed all 43 selected cases, including all 17 TrafficOriginTests, AnalyticsTests, DashboardActivityRetentionTests and DashboardSessionActivityTests, with no skips or warnings. Old-database migration, historical snapshots, repeated rollups, legacy byte/call totals and strict native envelopes are covered. Finite isolated run receipts and TRX hashes are in `artifacts/node-noop-runs/origin-*`.

Production scope is RelayRequestGuard.cs, CallTelemetry.cs, ApplicationPorts.cs, SqliteStore.Activity.cs, AnalyticsService.cs and Views.sql, plus reference documentation and TrafficOriginTests.cs. Adapter producers remain Claude's separate scope. Compaction, ReplyAddOns, dashboard changes, native activation and live deployment are excluded. Focused verification is complete; Manager owns independent review, batch integration and the next gate/deployment decision.
