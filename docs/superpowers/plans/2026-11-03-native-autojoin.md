# Native autojoin and stable participants implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement the tasks in order. Checkboxes track execution, not work completed during planning.

**Goal:** Opening a supported native chat in a configured checkout joins exactly once. Its next CoCern call uses its own session, and the hub can recognize that same participant after the session is replaced.

**Architecture:** Keep the native binding in the adapter's existing private handoff/wake storage and the verified participant on the existing hub session/directory record. Use one join operation for a startup command hook and the first stamped MCP call. Leave the raw session API and its authorizations intact. Do not add a service, a role, a user setting, a second tool transport, or a display-name identity registry.

**Tech stack:** Existing .NET 10 adapter and setup/launcher, Orleans control/session aggregates, current durable state, xUnit, installed Claude Code and Codex hooks.

**Spec:** [Auto-connect design, part 1](../specs/2026-11-03-auto-connect-design.md). Producer for [chat decisions, task 3](2026-11-03-chat-decisions.md); [permanent wake integration](2026-11-03-permanent-wake-integration.md) already exists.

## Global constraints

- One user chat is one participant. Namespace the native ID by client, authenticated principal, repository and canonical checkout (machine plus actual Git top-level). A label, a title, an agent ID, a matching folder, a shared connection, a recent call or a transcript is never evidence of identity. No binding transfers between different PCs, checkouts or principals.
- Preserve current principal/repository authorization and all client permission decisions. An installed helper is not proof of Paul's words, authority to grant privileges, or permission to execute a tool. No goal policy, peer directory merge/name resolver, message delivery, file claims, updater, manager/role reassignment or automatic action recovery here.
- Each C# task: load roslyn-codelens:roslyn-codelens first; connect Roslyn to the absolute feature CoCern.slnx and check the Visual Studio MCP solution/debugger separately. Keep the running primary VS checkout read-only. Use semantic source/references/diagnostics. Produce test binaries only under isolated artifacts. Do not install into live clients, interrupt real sessions or change live grants/approval policies for development tests.
- For dotnet tests below, run from the feature root: `dotnet test tests/CoCern.Tests/CoCern.Tests.csproj --artifacts-path artifacts/native-autojoin --results-directory artifacts/native-autojoin/results --logger trx -m:1 --filter "FullyQualifiedName~NativeJoin"`. Each task adds its named tests to this filter. Get an assertion failure, not just a discovery/compilation failure, before GREEN. Commit the reviewed file set for each task separately under the manager's existing integration policy. No AI attribution.

## Review focus

1. Two chats with identical labels share one adapter while two independent processes race registration for one chat; retries across restart, including a lost open reply, must never open another session or reuse a neighbor's handle (tasks 1–3).
2. A raw caller, a guessed native ID, stale stamp, relabeled handle, changed principal, different checkout or malicious tool argument must not yield a peer token, change identity, or elevate a grant (tasks 1–4).
3. Compaction, fork, clear, delegation and same-ID resume mean different things. Unknown lineage must not silently acquire another participant's work (tasks 1, 4–5).
4. An old session may own unread mail or unsettled work when it appears obsolete, or reappear after fenced closure. Block/action/restoration state stays with that original session; it must not become the participant's current session by arriving last (task 2).
5. An installed hook may be untrusted, skipped, stale after launcher swap, or rewrite authorization as well as inputs. An authenticated inbox, green helper test or reachable directory row proves neither identity capture nor a native wake (tasks 4–5).

## Evidence and provider gate

The inspected feature solution has `ChatCalls.CallAsync`/`Learn` and one `CurrentSession` per `CoordinationTools.Create`; `ForwardedTool.InvokeAsync` currently forwards the argument dictionary. `SessionHandoff.RecordLocal` and `Restore` plus `LocalChatWake.Observe` already guard writes using authenticated session replies and private connection files. Node and explicit-token modes both need the stamped capture. A known local Codex participant could read its authenticated inbox but had an unmapped handle lacking both Client and Chat; its follow-up after the turn ended did not start a turn. Do not repair that record by guessing. Do not treat the absence of a node process as absence of an in-process watcher or local `reachable:false` as a model-wake observation.

Installed version/help checks: Codex CLI 0.166.0-alpha.5.1 supports resume/fork and hook trust; Claude Code 2.1.317 supports session/fork/resume. Help and matching strings in an executable do **not** establish fields on a real MCP call. [Codex hook reference](https://developers.openai.com/codex/hooks/) documents common `session_id` (parent session for subagent hooks) and `cwd`, SessionStart `source` including fork, PreToolUse `tool_name/tool_use_id/tool_input`, and nested code-mode MCP calls. A synchronous command hook replaces the entire argument object with `hookSpecificOutput.updatedInput` and currently requires `permissionDecision:"allow"`. An MCP-tool SessionStart handler may run before the connection exists and cannot reconnect it. [Claude hook reference](https://code.claude.com/docs/en/hooks) documents common `session_id/cwd`, optional agent fields, the optional custom `session_title`, start source, and whole-object PreToolUse replacement **without** a permission decision. Do not set Claude's decision to allow. Codex does not document a chat title in these common/start fields. Use a supplied title only as display text; otherwise use the existing provider display label. Neither checked contract identifies an authoritative previous native ID for changed-ID continuation. Fork, source=resume, and agent_id are not continuation links.

**Blocking activation gate, not a dependency on Paul's live settings:** Before enabling a provider's hooked MCP surface, use an isolated installed client and disposable CoCern setup. Compare unchanged-client baseline with the proposed command hooks for the same allowed, ask-before-use and forbidden CoCern operations. Prove a denied operation makes zero real calls, an ask still waits and cancellation makes zero calls, and an allowed call executes once with the actual native stamp (including Codex code mode). Record sanitized event/field names, stable equality of IDs and native prompts only. No real tokens/tool payloads. Do not install trust bypasses, invent an alternative permission policy or assume that Codex PreToolUse allow has no effect on MCP approval. If this fails, or client tool-schema validation rejects the post-hook stamp, leave that client on its unchanged raw registration. No supported permission-neutral Codex rewrite or authenticated per-call replacement metadata has been demonstrated on the installed build. A binary string, process environment, optional request metadata without a documented and exercised per-call guarantee, and the spike are not alternatives. Shared hub/adapter tasks and provider-independent Standing recording remain executable. The full dual-client milestone is gated, not declared impossible.

Separate adapter-origin/credential scopes; the hub supplies the actual principal, never the hook.
