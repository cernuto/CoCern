## Findings

1. **P1. Prove the existing launcher before changing its profile.** `src/CoCern.Adapter/Setup/NativeActivation.cs:41,63–76` uses `RepairCommand.OwnsCodexNode` or the Claude settings environment to recognize ownership. `src/CoCern.Adapter/Setup/RepairCommand.cs:228–231` accepts an empty environment for the default node folder. The Codex promotion could replace another program's command and arguments in a table named `cocern`. The Claude file-claim plan can arm handlers when the configured server uses ordinary transport or another executable. `NativeRegistration.Read` also accepts local credential caches. Require explicit enrollment and match the actual launcher and arguments to the owned connection, profile and expected standard/native mode. Bind the candidate's hook commands to that same supported helper and reject unsupported development or historical commands.

2. **P1. Keep every ownership input pinned at apply.** `src/CoCern.Adapter/Setup/NativeSettingsTransaction.cs:18–31,46–63` replans before locking and locks only the hook file for file-claim changes. Its final verification rereads registration but does not compare its definition to the preview or recheck the launch configuration. If another writer switches Codex's config.toml or Claude's .claude.json between replan and write, the hooks can be installed in a profile that now points elsewhere. Capture the expected credential/candidate identity and launcher file snapshots, hold the ownership inputs against writes through the commit, and validate the locked data before changing settings. For promotion, refuse a globally disabled hook configuration before changing transport, as `NativeActivation.PlanPromotion` at lines 44–54 currently prepares the native launch even when those handlers cannot stamp calls.

3. **P1. Bind POST lifecycle handlers to the profile.** `src/CoCern.Adapter/Setup/NativeActivation.cs:82–85` includes the profile for PRE but omits it for POST success and failure. `src/CoCern.Adapter/Node/NativeEditLifecycleHook.cs:46–53` checks the registered profile only when supplied. A stale or copied installed POST handler can therefore reach the lifecycle processor after registration changes. Include the expected profile in both POST handlers and keep registration validation mandatory for this owned path. Preserve the existing checkout, generation and invocation fences.

4. **P2. Make every admitted transaction recoverable within the reader's bounds.** `src/CoCern.Adapter/Setup/NativeSettingsTransaction.cs:62–65,78–81,109–110` serializes a journal before enforcing its four MiB recovery limit. Two roughly 850 KiB settings files and their equally large after-images exceed that journal limit after Base64 encoding. An after-image can also exceed the one MiB settings reader limit. A crash can leave a perfectly valid before/after pair that Recover will never read. Serialize and size-check before mutation, check each after-image against the recovery cap and skip writes to unchanged targets.

5. **P2. Keep current chats eligible for catalog refresh.** `src/CoCern.Adapter/ToolSurface.cs:59–68` retains every observed session forever and drops a new session at 1,024 entries. After enough legitimate chat churn, a newly opened standard session retains its predecessor's catalog and local allow/deny decision, regardless of its authenticated hub setting. A new native chat likewise cannot contribute to the union. Store only the active standard selection. Retire or evict old native observations under the bound so current sessions are admitted. The hub's per-call profile check still governs authorization.

6. **P1 delivery gap. No supported preview, apply or recovery entry point.** `src/CoCern.Adapter/Setup/NativeActivation.cs:12–31` has a private evidence constructor with no issuer, and collection always returns null. Promotion always refuses, as it should until an authenticated permission source exists. The file-claim planner contains concrete PRE and POST definitions, but Roslyn found no caller of `NativeSettingsTransaction.ApplyFileClaims`, `ApplyPromotion` or `Recover` (`src/CoCern.Adapter/Setup/NativeSettingsTransaction.cs:12–22,73`). The only caller of `PlanFileClaims` is the unused apply method. Provide a reachable read-only preview/refusal and an explicit supported file-claim operation after the ownership and recovery fixes. Keep ordinary setup unchanged and native activation closed until an authorized issuer exists. Record the missing issuer separately from future runtime verification.

## Native rereview and second-pass follow-up

The new `--native-activation` dispatch exposes explicit preview, confirmation, apply and recovery. The confirmation is a same-user operator attestation. The interactive command refuses redirected input/output, displays the selected provider/profile/helper/candidate/enrollment, asks the operator to verify four outcomes, then signs a five-minute private receipt with the enrolled credential. This implements the reviewed human-confirmation option. No confirmation or provider permission check ran during review.

The revised source requires an enrolled credential, exact current launch and candidate definitions, refuses globally disabled hooks, includes the profile in both POST handlers, locks and hashes the additional ownership files, rejects oversized recovery journals and skips unchanged writes. The initial findings about the missing issuer/command, profile-less POST, unchecked recovery size and weak environment-only launcher check are superseded. Two additional native findings affect the newly reachable workflow:

1. **P1. Use shell-literal quoting for Claude hook commands.** `src/CoCern.Adapter/Setup/NativeActivation.cs:157–165` combines POSIX environment assignment with `SetupEnvironment.AdapterCommandLine` and `LogonStart.Quote`, which encodes Windows argument-vector quoting. A profile/folder or executable path containing a dollar expansion or backticks is interpolated by a POSIX shell even when surrounded by double quotes. In a valid path containing command substitution, executing a hook can execute an unintended command. Use literal quoting for the actual hook shell for the launcher and all arguments, or explicitly refuse unsupported paths when constructing and matching definitions. Do not accept an unsafe historical candidate as current.

2. **P2. Detect installed file-claim hooks from an earlier helper.** `src/CoCern.Adapter/Setup/NativeActivation.cs:154–173,239–264` reconstructs only the current helper's exact commands. After an owned update changes the helper path, `CodexNativeSetup.RefreshEnrolledNative` updates its normal native hooks, but its exact-command match does not update the extra file-claim handlers. Disable can then report success/unchanged while the old handlers remain, and enable can add new duplicates. Keep private exact installed definitions for reversal, or refuse the operation with specific recovery guidance when historical owned handlers are present. Preserve any user-edited handlers.

Re-reviewed two second-pass fixes. `Operations.IsRead` now lists all three goal query constants, which avoids an extra durable board commit per successful probe. `RelayApplication.RunStagesAsync` now fits settings before the proposal reservation and uses the bounded session-open result. The recipient-aware active-goal projection and standing-order offer work were still changing at this checkpoint.

Re-reviewed the finished projection and offer changes. `StandingPreferences.Delivered` now excludes private-binding and task-marker goal IDs from ordinary grants. These changes resolve second-pass findings 2 and 5 for the reported triggers.

- **P1.
